# Monthly release checklist

- [ ] Choose the public year/month and issue number; keep internal revisions separate.
- [ ] Lock the roster, titles, authors/tools, source paths and license provenance.
- [ ] Try a small enjoyable slice of each interactive piece before expanding it.
- [ ] Verify native-resolution text, graphics, controls and readable article paging.
- [ ] Check gameplay boundaries, inventory, restart/skip and error paths.
- [ ] Test each child from a nested issue directory, repeated returns, missing files,
      caller restoration, video/cursor and sound/vector cleanup.
- [ ] Measure state/memory; state the exact emulator configuration and hardware limits.
- [ ] Audit complete source/asset correspondence; exclude proprietary/private payloads.
- [ ] Build a clean FAT12 720 KB data image and matching folder ZIP. Measure cluster
      allocation and free space; keep sources and diagnostics in companion files.
- [ ] Run host tests and package validation on exact final bytes; record checksums.
- [ ] Publish source at an exact commit/tag and direct disk/folder/source/instruction assets.
- [ ] Confirm CI and anonymous download hashes; report physical tests still pending.
- [ ] Preserve the previous issue/revision and collect reader feedback for next month.
